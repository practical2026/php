Practical 1 Install Git and configure identity

Aim: Install Git for Windows and configure the identity recorded in commits.

Procedure
1.	Visit https://git-scm.com/downloads/win and download Git for Windows. 
2.	Run the installer. 
3.	Keep Git Credential Manager enabled and select the PATH option that allows Git from the command line and third party software. 
4.	Use the recommended Windows line ending option. 
5.	Finish installation.
6.	 Close and reopen Command Prompt, then check that Git is found.
git --version
where git
7.	Configure your actual identity. A GitHub verified email or your GitHub no-reply email can be used.
git config --global user.name "Student Name"
git config --global user.email "student@example.com"
git config --global init.defaultBranch main
git config --global --list

Practical 5 Resolve conflicts and undo practice changes

Aim: Create a controlled merge conflict, resolve it, unstage and discard a temporary edit, and revert a commit.

Procedure
1. Create the project and Java package directories.
cd /d D:\DevOpsLab

<project xmlns="http://maven.apache.org/POM/4.0.0"

         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0

Practical 11 Write and run JUnit tests

Aim
Execute three automated tests, observe a deliberate failure and repair it.

Procedure
1. Save the following code as src\test\java\com\example\AppTest.java.
package com.example;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class AppTest {
    @Test
    void addsPositiveNumbers() {
        assertEquals(30, App.add(10, 20));
    }

    @Test
    void addsZero() {
        assertEquals(7, App.add(7, 0));
    }

    @Test
    void addsNegativeNumbers() {
        assertEquals(-5, App.add(-2, -3));
    }
}
2. Execute tests and locate reports.
mvn clean test
dir target\surefire-reports
type target\surefire-reports\com.example.AppTest.txt
3. Temporarily change the positive-number assertion from assertEquals(30, ...) to assertEquals(31, ...). Save and run mvn test. Record the failing assertion and nonzero build result. Do not change the correct implementation just to satisfy an incorrect test.
4. Restore the expected value to 30, save, rerun and package.
mvn clean verify

Practical 15 Pipeline two for checkout test and package

Aim
Build the GitHub Maven project in separate pipeline stages and publish evidence.
Procedure
1. Create a Pipeline job named calculator-pipeline. Select Pipeline script. Paste the script below, replacing YOUR_USERNAME.
pipeline {
    agent any
    tools {
        jdk 'JDK21'
        maven 'Maven3'
    }
    options { disableConcurrentBuilds() }
    stages {
        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/YOUR_USERNAME/student-calculator.git'
            }
        }
        stage('Compile') {
            steps { bat 'call mvn -B clean compile' }
        }
        stage('Test') {
            steps { bat 'call mvn -B test' }
        }
        stage('Package') {
            steps { bat 'call mvn -B package -DskipTests' }
        }
        stage('Run') {
            steps {
                bat 'java -jar target/student-calculator-1.0.0.jar'
            }
        }
    }
    post {
        always {
            junit testResults: 'target/surefire-reports/*.xml',
                  allowEmptyResults: true
        }
        success {
            archiveArtifacts artifacts: 'target/*.jar',
                             fingerprint: true
        }
    }
}
2. For private SCM, add credentialsId: github-read to the git step as another named argument with correct commas. 
3. Save and Build Now. Check the console of each stage. Verify that Test runs three tests, Run prints Sum = 30, and the JAR is archived.
4. Note that allowEmptyResults permits report publishing after an early checkout or compile failure. It does not erase a failed Maven command. In a successful run, explicitly check that the report contains the expected tests; an empty report is not valid completion.

Practical 16 Pipeline three stored in a Jenkinsfile

Aim
Store the CI pipeline in GitHub and load it through Pipeline script from SCM.

Procedure
1. Save the following complete script as Jenkinsfile with no extension in the project root. deleteDir clears only the current Jenkins workspace before a fresh checkout; do not point this job at your personal source folder.
pipeline {
    agent any
    tools {
        jdk 'JDK21'
        maven 'Maven3'
    }
    options {
        disableConcurrentBuilds()
        buildDiscarder(logRotator(numToKeepStr: '10'))
        timeout(time: 15, unit: 'MINUTES')
        skipDefaultCheckout(true)
    }
    parameters {
        booleanParam(name: 'RUN_APP', defaultValue: true,
                     description: 'Run the packaged calculator')
    }
    stages {
        stage('Checkout') {
            steps {
                deleteDir()
                checkout scm
            }
        }
        stage('Verify') {
            steps { bat 'call mvn -B clean verify' }
        }
        stage('Run') {
            when { expression { return params.RUN_APP } }
            steps {
                bat 'java -jar target/student-calculator-1.0.0.jar'
            }
        }
    }
    post {
        always {
            junit testResults: 'target/surefire-reports/*.xml',
                  allowEmptyResults: true
        }
        success {
            archiveArtifacts artifacts: 'target/*.jar',
                             fingerprint: true
        }
        failure { echo 'Inspect checkout, compilation and test logs' }
    }
}
2. Commit and push the file.
cd /d D:\DevOpsLab\student-calculator
git switch main
git pull --ff-only
git add Jenkinsfile
git commit -m "Add CI pipeline as code"
git push origin main
3. Create a Pipeline job named calculator-ci. Under Pipeline, choose Pipeline script from SCM. SCM: Git; Repository URL: your student-calculator HTTPS URL; Branch Specifier: */main; Script Path: Jenkinsfile. Choose github-read only if the repository is private.
4. Save and Build Now once. The first run registers the parameter; subsequent runs show Build with Parameters. Run with RUN_APP true and then false. Confirm that false skips only the Run stage; verification and artifact publication still execute.
5. Inspect the checkout commit hash, three-test report and archived JAR. The 15-minute timeout is a lab value; on a slow first dependency download, investigate and adjust it deliberately. This job demonstrates CI and artifact production, not deployment to a server.
